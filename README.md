# MyReview · 个人面试练习工作台

单机自用的面试练习 Web 应用：练习（真考卷式）、押题（简历押题）、模拟面试、系统设置。
目标是能长期用的面试冲刺复习工具。

## 一张卷就是一张真考卷

**满分 100 分，前易后难**，常规卷的三档结构：

| 档 | 题型 | 题量占比 | 每题分值 | 分值占比 |
|---|---|---|---|---|
| 基础 | 概念辨析 / 简答 | ~55% | 2-4 分 | ~30% |
| 中档 | 原理追问 / 小场景 | ~30% | 4-8 分 | ~35% |
| 大题 | 场景应用 / 故障排查 / 方案设计 | **1-2 道** | 15-20 分 | ~35% |

前面是基础小题，**最后 1-2 道才是场景大题**——一个完整业务场景 + ①②③ 三个子问题，
像数学大题，一次作答分点评分。场景题太多用户会疲劳。

每题分值合计正好 100（`Scoring.normalizePoints` 会把 AI 算歪的分值校正回来，
大题夹在 15-20、中档 4-8、基础 2-4）。

### 组卷模式（这卷出哪些档）

点「开始出题 / 继续出题」时选，**挂每张卷**——同一练习里可以今天练基础、下周做深入：

| 模式 | 出什么 | 题量 | 适用 |
|---|---|---|---|
| **常规** | 基础+中档+大题混排 | 按建练习时的题量档（6/10/15） | 像真考卷一样完整练一套 |
| **基础** | 只出基础小题 | ~25 题 | 打牢概念与记忆 |
| **提升** | 只出中档 | ~14 题 | 练原理追问与小场景 |
| **深入** | 只出大题 | ~5 题 | 练完整场景与方案设计 |
| **基础强化** | 基础+中档 | ~20 题 | 巩固薄弱概念 |
| **中档提升** | 中档+大题 | ~10 题 | 向场景题过渡 |

- **总分恒 100、档位分值区间不变**；题量随模式变，就是为了让区间能成立
- 混排模式的具体配比由**掌握度**决定（熟了才配场景题），内容深浅由**复习强度 + 点上规格**管
- 建练习时的「一卷题量」**仅常规模式生效**
- 串联大题只在含大题的模式下出（常规 / 深入 / 中档提升）；期末考与错题卷不走这套

### 出题的四条硬约束

1. **一题只考 1-2 个知识点**——禁止把多个知识点串成一道综合大题
2. **内容深度严格照规格出**——每个点在拆清单时就声明了三档各考到哪为止，出题禁止超出规格往源码里挖
3. **严格在范围内**——Java 基础里不许出现 Redis/分布式/微服务
4. **变种是换角度，不是加深**——上一卷没答好的点，下一卷换问法再考，还在同一档规格内

### 岗位难度

建练习时选 **初级 / 中级 / 高级**：

- 初级：只考常用与常见，**不出场景大题**
- 中级：重点是原理与落地，不要求答出源码细节（这是默认）
- 高级：可考方案取舍与架构权衡

### 复习强度（一刷/二刷/三刷）

建练习时选 **速通 / 标准 / 深挖**，决定两件事：① 按哪一档内容规格出题；② 哪些优先级的点进题池：

| 强度 | 内容规格 | 点池 | 用法 |
|---|---|---|---|
| **速通** | 是什么、怎么用、什么场景选 | 仅高频点 | 一刷、考前冲刺 |
| **标准** | 主干流程、关键参数、为什么这么设计 | 高频+常见 | 二刷、日常（默认） |
| **深挖** | 边界陷阱、取舍对比（天花板，不碰源码） | 全量 | 三刷、查漏、高级岗 |

**深度不靠出现次数自动加深**——强化靠换角度变种，内容天花板写死在点上。

### 知识点的重要度从哪来

拆清单时自动**联网搜 5 条切口**（高频面试题/真题/八股文/源码向/场景题），
AI 对照搜索结果给每个点分级（high/medium/low），**证据落库可查**（`evidenceJson`）。
搜索挂了就降级为 AI 常识分级并标 `fallback`。速通只出 high，标准出 high+medium，深挖才碰 low。

## 练习流程

1. **开始出题** —— 选好**组卷模式**，AI 先定出卷计划（题量 + 每题角度/档位/题型/分值），再分批**并发出题**，
   一次给出一整卷（含参考答案）。后台任务，可看进度、可断点续跑。
   出题前会**联网搜当前高频面经线索**，避免出过时的题。
2. **答题** —— 逐题作答，保存作答**不调 AI**，保存后直接进下一题。
   题号上会打勾标记已作答。**参考答案默认不给看**。
3. **看参考答案** —— 要先确认：看过就**本题计 0 分**（前后端口径一致）。
4. **交卷** —— 后台批量批改、写本卷总结，更新**长期记忆**与**会话摘要**，并自动重出**阶段总结**。
   **没作答的题按「不会」处理**，会作为薄弱点写进记忆，并给出该记住什么。
5. **继续出题** —— 同一练习里再出一卷，带上记忆与摘要，避开已覆盖的点、向薄弱点推进。
6. **全复习** —— 基于阶段总结自动发起，范围是总结框定出的一长串文字。

> 练习与阶段**都没有「结束」**，一直保留。想收尾就新建一个阶段 / 练习。

## 容量上限

| 限制 | 默认 | 改哪 | 超了 |
|---|---|---|---|
| 每阶段练习数 | 50 | `Limits.MAX_PRACTICES_PER_STAGE` | 提示新建阶段 |
| 每练习卷数 | 20 | `Limits.MAX_PAPERS_PER_PRACTICE` | 提示新建练习 |

日常使用碰不到，只是防止数据无限膨胀。

## 语音作答（语音转文字）

答题页有「语音作答」按钮：按下录音、再说一次结束，识别出的文字**立刻追加进作答框**，
你可以改完再点「保存并下一题」。语音和打字是同一条作答路径。

- 引擎：**sherpa-onnx + Paraformer**（Apache 2.0），**本地识别、不联网**，音频不外传
- 录音上限 3 分钟；浏览器端转成 16kHz 单声道 WAV 再传后端
- 实测：7 条真实音频全部识别正确，单条 **56-99ms**（中英混合、方言、8kHz 都支持）；
  最长 3 分钟 / 5.5MB 也能正常识别

### 术语自动纠正

中文模型的英文词表有限，技术术语容易被认成同音词（equals → ecos）。
识别出的文字会**立刻显示**，同时后台调一次 AI 把术语改回正确写法，几秒后原地替换。

```
识别原文：我觉得 ecos 方法和 hashCode 方法要一起重写，还有瓦太奥 关键字保证可见性
↓ 自动纠正
纠正后：  我觉得 equals 方法和 hashCode 方法要一起重写，还有 volatile 关键字保证可见性
```

只改术语、**不改口述内容**；你已经动手改过就不会被覆盖。

### 装模型（一次性）

模型要自己下载到 `data/models/paraformer-zh/`，目录里需要 `model.int8.onnx` 与 `tokens.txt`。

**Windows PowerShell**（注意 `curl.exe` 的 `.exe` 后缀，否则 PowerShell 会当成 `Invoke-WebRequest`；
`--ssl-no-revoke` 是为了绕开 schannel 查不到证书吊销状态的问题）：

```powershell
# 完整版（约 950MB，准确率最高，推荐）
curl.exe -L --ssl-no-revoke -o p.tar.bz2 https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-paraformer-zh-2024-03-09.tar.bz2

tar -xf p.tar.bz2
New-Item -ItemType Directory -Force data/models | Out-Null
Move-Item sherpa-onnx-paraformer-zh-2024-03-09 data/models/paraformer-zh
```

下载慢就把 `https://github.com/` 换成 `https://gh-proxy.com/https://github.com/`。

小模型只有 74MB（`...-zh-small-2024-03-09`），够用、秒下。

**Linux / macOS**：

```bash
curl -L -o p.tar.bz2 https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-paraformer-zh-2024-03-09.tar.bz2
tar xjf p.tar.bz2 && mv sherpa-onnx-paraformer-zh-2024-03-09 data/models/paraformer-zh
```

> ⚠️ **别下错**：`paraformer-zh-int8-2025-10-07` 是**四川话**模型。
> 普通话要用 `paraformer-zh-2024-03-09`。

模型目录可以在「系统设置 → 语音识别」里改。没装模型时语音按钮置灰并说明原因，**其他功能不受影响**。

## 出题模式

| 模式 | 填什么 | 适用 |
|---|---|---|
| **主题模式** | 一个主题词，如「集合、泛型、反射」 | 说不清范围时，让 AI 围绕主题展开 |
| **范围模式** | 自然语言描述整份资料的范围 | 「范围是 javaguide 基础篇上中下，参照 xxx」 |

> **范围模式里的 URL 会被真的抓下来读正文**。工具用 jsoup 抽正文（去掉脚本/导航/页脚），
> 抓一次存进 `sources.json`，出题时把正文喂给 AI。
> 读不到时**如实报错**（纯前端渲染的站点、需登录/有反爬的、PDF）并提示粘正文，绝不装作读过。

## 阶段总结 vs 实时统计（别混）

| | 实时统计 | 阶段总结 |
|---|---|---|
| 是什么 | 几张卷、多少题、平均分 | **AI 给的反馈** |
| 怎么来 | 查询现算，不落库 | 交卷后自动重新生成 |
| 存哪 | 不存 | `stages.summaryJson` |
| 用途 | 看进度 | **全复习的唯一依据** |

阶段总结的输入是**固定格式**：做了哪些练习、记忆内容、平均分、**每次考试的 AI 评价**。
输出包含 `reviewScope`——为全复习框定的范围，一长串连贯文字。

**全复习**本质是系统自动创建的一个练习（`review=true`），
它的范围不是用户写的，而是 `summary.reviewScope`。**没有阶段总结就不能发起全复习**（接口会拒绝，按钮应禁用）。

## 记忆体系（不丢失 + 精简）

| 层 | 存哪 | 什么时候更新 | 硬上限 |
|---|---|---|---|
| L1 长期记忆 | `Practice.memoryJson` | 每次交卷 | 每类 ≤8 条、每条 ≤30 字；coverage ≤40 条 |
| L2 会话摘要 | `Practice.digestJson` | 每次交卷 | 全文 ≤400 字 |
| L3 阶段总结 | `Stage.summaryJson` | 每次交卷（自动） | reviewScope ≤600 字 |

**为什么不丢**：`coverage`（已覆盖知识点）走**并集累积**，服务端 merge、只增不减，
AI 只负责蒸馏措辞。压缩的是说法，不是知识点本身。

**上下文为什么不会超长**：LLM 调用本身是无状态的（每次独立 prompt），
所以「上下文过长」只可能来自 prompt 膨胀。出题 prompt 每段硬上限 + 总预算：

```
system(固定)
+ 范围描述     ≤ 2000 字
+ 网上资料正文  ≤ 6000 字
+ L2 摘要      ≤  600 字
+ L1 记忆      ≤ 1200 字
+ 最近历史     ≤ 15 条（超预算从最旧往回砍）
            ─────────────────────────
                总计 ≤ 12000 字
```

单次 prompt 长度永远有顶。练习 `complete` 时会写一份**收尾总结**（纯本地、永不失败），
恢复会话时直接读它，无缝衔接。

## 断点续跑（客户端无感衔接）

出题与批改都是**后台任务**：发起即返回，进度写在 `Paper.progressJson`，
每批一成功就落库。所以：

- 刷新页面、关掉浏览器重开，进度照样看得到（数据在库）
- AI 中途挂了 / 部分批次失败，点「续跑」从 `Paper.planJson` 的断点接着出
- 同一张卷同时只允许一个任务，重复点按钮会被拒绝

## 数据存储

- 业务数据存本地 JSON 文件（`data/store/*.json`），无数据库
- 存储层是接口抽象（`com.review.vt.repo`），换数据库只需新增 `repo.jpa.Jpa*Repository` 实现同名接口
- 读入时忽略未知字段，字段增删后旧数据仍可无损读入

## 提示词与实现

出题 / 批改 / 总结的提示词在 `service/PromptTemplates.java`：

- **出题铁律**：像真考卷一样前易后难（档位构成由组卷模式定死，模型照每题标注的档位写）；
  大题必须带完整业务场景
  （业务背景、系统现状、约束或线上现象），基础题写得短而准；参考答案「先结论、再原理」，
  **只在题面要求方案/做法时**才给落地取舍，严格覆盖「本题要求」（demands）。
- **批改标准 = 本题要求**：出题时 AI 顺带产出 `demands`（基础/中档 1-2 条，大题 3 条对应 ①②③），
  批改只按它逐条核对。参考答案多写的内容不得判「缺失」、不得扣分，只能进「扩展」段（不加分不扣分）。
  但要求内答错、答浅（问「为什么」只给结论）、漏项照常重扣——不是宽松大师。
- **两步出卷**：先出计划（角度 + 档位 + 题型 + 分值），再按角度分批并发出题，
  单批 5 题（模型思考会吃输出额度，批次不能大），单批失败自动重试一次。
- **交卷三件事并行**：本卷总结 / 记忆更新 / 摘要更新 拆成三个并行小调用，
  各自输出都很短，避免长 JSON 被截断。
