# MyReview · 个人面试练习工作台

单机自用的面试练习 Web 应用：练习（真考卷式）、押题（简历押题）、模拟面试、系统设置。
目标是能长期用的面试冲刺复习工具。

## 一张卷就是一张真考卷

**满分 100 分，前易后难**，三档结构：

| 档 | 题型 | 题量占比 | 每题分值 | 分值占比 |
|---|---|---|---|---|
| 基础 | 概念辨析 / 简答 | ~45% | 2-3 分 | ~30% |
| 中档 | 原理追问 / 小场景 | ~35% | 4-6 分 | ~35% |
| 大题 | 场景应用 / 故障排查 / 方案设计 | ~20% | 8-15 分 | ~35% |

前面是基础小题，**最后几道才是场景大题**——和真实考试一样。每题分值合计正好 100
（`Scoring.normalizePoints` 会把 AI 算歪的分值校正回来）。

## 练习流程

1. **开始出题** —— AI 先定出卷计划（题量 + 每题角度/档位/题型/分值），再分批**并发出题**，
   一次给出一整卷 15-30 题（含参考答案）。后台任务，可看进度、可断点续跑。
   出题前会**联网搜当前高频面经线索**，避免出过时的题。
2. **答题** —— 逐题作答，保存作答**不调 AI**，保存后直接进下一题。
   题号上会打勾标记已作答。**参考答案默认不给看**。
3. **看参考答案** —— 要先确认：看过就**本题计 0 分**（前后端口径一致）。
4. **交卷** —— 后台批量批改、写本卷总结，更新**长期记忆**与**会话摘要**，并自动重出**阶段总结**。
5. **继续出题** —— 同一练习里再出一卷，带上记忆与摘要，避开已覆盖的点、向薄弱点推进。
6. **全复习** —— 基于阶段总结自动发起，范围是总结框定出的一长串文字。

> 练习与阶段**都没有「结束」**，一直保留。想收尾就新建一个阶段 / 练习。

## 容量上限

| 限制 | 默认 | 改哪 | 超了 |
|---|---|---|---|
| 每阶段练习数 | 50 | `Limits.MAX_PRACTICES_PER_STAGE` | 提示新建阶段 |
| 每练习卷数 | 20 | `Limits.MAX_PAPERS_PER_PRACTICE` | 提示新建练习 |

日常使用碰不到，只是防止数据无限膨胀。

## 模型接入

系统设置里填 **API Base / API Key / 模型 / 接口协议**：

| 协议 | 端点 | 典型 |
|---|---|---|
| `anthropic` | `{base}/v1/messages` | Claude / mimo |
| `openai` | `{base}/v1/chat/completions` | DeepSeek / 通义 / Ollama / vLLM |

切换协议不用改代码。

## 出题模式

| 模式 | 填什么 | 适用 |
|---|---|---|
| **主题模式** | 一个主题词，如「集合、泛型、反射」 | 说不清范围时，让 AI 围绕主题展开 |
| **范围模式** | 自然语言描述整份资料的范围 | 「范围是 javaguide 基础篇上中下，参照 xxx」 |

> **范围模式里的 URL 会被真的抓下来读正文**。工具用 jsoup 抽正文（去掉脚本/导航/页脚），
> 抓一次存进 `sources.json`，出题时把正文喂给 AI。
> 读不到时**如实报错**（纯前端渲染的站点、需登录/有反爬的、PDF）并提示粘正文，绝不装作读过。

## 阶段总结 vs 实时统计（别混）

| | 实时统计 | 阶段总结 |
|---|---|---|
| 是什么 | 几张卷、多少题、平均分 | **AI 给的反馈** |
| 怎么来 | 查询现算，不落库 | 交卷后自动重新生成 |
| 存哪 | 不存 | `stages.summaryJson` |
| 用途 | 看进度 | **全复习的唯一依据** |

阶段总结的输入是**固定格式**：做了哪些练习、记忆内容、平均分、**每次考试的 AI 评价**。
输出包含 `reviewScope`——为全复习框定的范围，一长串连贯文字。

**全复习**本质是系统自动创建的一个练习（`review=true`），
它的范围不是用户写的，而是 `summary.reviewScope`。**没有阶段总结就不能发起全复习**（接口会拒绝，按钮应禁用）。

## 记忆体系（不丢失 + 精简）

| 层 | 存哪 | 什么时候更新 | 硬上限 |
|---|---|---|---|
| L1 长期记忆 | `Practice.memoryJson` | 每次交卷 | 每类 ≤8 条、每条 ≤30 字；coverage ≤40 条 |
| L2 会话摘要 | `Practice.digestJson` | 每次交卷 | 全文 ≤400 字 |
| L3 阶段总结 | `Stage.summaryJson` | 每次交卷（自动） | reviewScope ≤600 字 |

**为什么不丢**：`coverage`（已覆盖知识点）走**并集累积**，服务端 merge、只增不减，
AI 只负责蒸馏措辞。压缩的是说法，不是知识点本身。

**上下文为什么不会超长**：LLM 调用本身是无状态的（每次独立 prompt），
所以「上下文过长」只可能来自 prompt 膨胀。出题 prompt 每段硬上限 + 总预算：

```
system(固定)
+ 范围描述     ≤ 2000 字
+ 网上资料正文  ≤ 6000 字
+ L2 摘要      ≤  600 字
+ L1 记忆      ≤ 1200 字
+ 最近历史     ≤ 15 条（超预算从最旧往回砍）
            ─────────────────────────
                总计 ≤ 12000 字
```

单次 prompt 长度永远有顶。练习 `complete` 时会写一份**收尾总结**（纯本地、永不失败），
恢复会话时直接读它，无缝衔接。

## 断点续跑（客户端无感衔接）

出题与批改都是**后台任务**：发起即返回，进度写在 `Paper.progressJson`，
每批一成功就落库。所以：

- 刷新页面、关掉浏览器重开，进度照样看得到（数据在库）
- AI 中途挂了 / 部分批次失败，点「续跑」从 `Paper.planJson` 的断点接着出
- 同一张卷同时只允许一个任务，重复点按钮会被拒绝

## 数据存储

- 业务数据存本地 JSON 文件（`data/store/*.json`），无数据库
- 存储层是接口抽象（`com.review.vt.repo`），换数据库只需新增 `repo.jpa.Jpa*Repository` 实现同名接口
- 读入时忽略未知字段，字段增删后旧数据仍可无损读入

## 跑起来

```bash
mvn spring-boot:run        # 打开 http://localhost:8080
mvn test                   # 单元测试
```

在「系统设置」里填 API Base / API Key / 模型，AI 出题、批改、总结才可用。

## 提示词与实现

出题 / 批改 / 总结的提示词在 `service/PromptTemplates.java`：

- **出题铁律**：像真考卷一样前易后难、三档齐全；大题必须带完整业务场景
  （业务背景、系统现状、约束或线上现象），基础题写得短而准；参考答案「先结论、再原理、最后落地取舍」。
- **两步出卷**：先出计划（角度 + 档位 + 题型 + 分值），再按角度分批并发出题，
  单批 5 题（模型思考会吃输出额度，批次不能大），单批失败自动重试一次。
- **交卷三件事并行**：本卷总结 / 记忆更新 / 摘要更新 拆成三个并行小调用，
  各自输出都很短，避免长 JSON 被截断。
