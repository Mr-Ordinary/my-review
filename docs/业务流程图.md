# MyReview 业务交互流程图

> 泳道：`用户` / `前端` / `后端` / `AI` / `存储`
> 目的：核对后端逻辑是否符合设想。前端 UI 尚未按此优化。

---

## 0. 概念与数据模型

```
阶段 Stage ── 只是一个名字，用来分组，没有业务含义
  │
  ├── 实时统计  ← 查询现算，不落库（几张卷 / 多少题 / 平均分）
  │
  ├── 阶段总结 summaryJson ← ★ AI 给的反馈，交卷后自动重新生成
  │      ├─ overall / strengths / keyWeaknesses / nextSteps
  │      └─ reviewScope：为「全复习」框定的范围，一长串文字
  │
  └── 练习 Practice ── 一个练习 = 一个会话，可反复出卷
        ├─ scopeMode: topic(主题) / range(范围)
        ├─ scopeText: 范围模式下的用户原话（可能含 URL）
        ├─ review: 是否系统发起的全复习
        ├─ memoryJson  ← L1 长期记忆
        ├─ digestJson  ← L2 会话摘要（兼作会话恢复依据）
        └── 卷 Paper ── AI 一次出的一批题，满分 100
              ├─ status: generating → answering → grading → graded
              ├─ planJson: 出卷计划（角度/档位/题型/分值），断点续跑用
              ├─ progressJson: {stage, planned, done, failed[], running}
              └── 题 Question（前易后难，三档）
                    ├─ tier: 基础(2-3分) / 中档(4-6分) / 大题(8-15分)
                    ├─ points: 本题分值，卷内合计 = 100
                    ├─ referenceAnswer: 出题时就给出（默认不给用户看）
                    ├─ revealedAt: 看过参考答案的时间 → 本题计 0 分
                    └── 作答 Attempt
                          ├─ score: 0-10 表现分（AI 给）
                          └─ points: 实得分 = score/10 × 该题分值

资料缓存 Source ── 范围里提到的 URL，抓一次存住
```

## 2. 出题（一次出一张卷，满分 100）

**关键点：发起即返回，后台跑，前端轮询进度；每批成功立刻落库，可断点续跑。**

```
 用户            前端                    后端                     AI              存储
  │ 点[开始出题]   │                       │                       │                │
  │ ────────────> │ POST /practices/{id}  │                       │                │
  │               │   /papers             │ 查有没有未交卷的卷      │                │
  │               │ ────────────────────> │ 有→拒绝                │                │
  │               │                       │ 无→建卷               │                │
  │               │                       │   status=generating    │                │
  │               │                       │ ────────────────────────────────────> │ papers.json
  │               │ <──────────────────── │ ★立即返回（0.02s）      │                │
  │               │                       │                       │                │
  │  看到进度条    │ (轮询 2.5s)           │ ┌──── 后台任务 ────┐   │                │
  │  已出 6/20    │ GET /practices/{id}   │ │                   │   │                │
  │               │ ────────────────────> │ │ ①抓范围里的 URL    │   │                │
  │               │ <──────────────────── │ │ ──────────────────────────────────>│ sources.json
  │               │                       │ │  (正文进上下文)     │   │                │
  │               │                       │ │ ①b 联网搜高频面经   │   │                │
  │               │                       │ │ ─────────────────>│ Bing 搜索     │
  │               │                       │ │  (校准时效性,搜不到 │   │                │
  │               │                       │ │   就降级不给线索)   │   │                │
  │               │                       │ │                   │   │                │
  │               │                       │ │ ②出卷计划          │   │                │
  │               │                       │ │ ────────────────> │ 20题+档位+分值 │
  │               │                       │ │ <──────────────── │ Σ分值=100     │
  │               │                       │ │ 校正分值到合计100   │   │                │
  │               │                       │ │ ──────────────────────────────────>│ papers.planJson
  │               │                       │ │                   │   │                │
  │               │                       │ │ ③按角度分批并发出题 │   │                │
  │               │                       │ │  (每批 5 题)       │   │                │
  │               │                       │ │ ────────────────> │ 题面+参考答案  │
  │               │                       │ │ <──────────────── │ +考察点        │
  │               │                       │ │ 每批成功→立刻落库   │   │                │
  │               │                       │ │ ──────────────────────────────────>│ questions.json
  │               │                       │ │ 更新进度 done/N    │   │                │
  │               │ <──────────────────── │ │                   │   │                │
  │  进度条在涨    │                       │ │ ④缺题则再补一轮     │   │                │
  │               │                       │ │  (模型偶尔少给题)   │   │                │
  │               │                       │ │                   │   │                │
  │               │                       │ │ ⑤全齐→             │   │                │
  │               │                       │ │  status=answering   │   │                │
  │               │                       │ │ ──────────────────────────────────>│ papers.json
  │               │                       │ └───────────────────┘   │                │
```

**卷的分值结构（像真考卷）**

| 档 | 题型 | 题量 | 每题分值 | 分值占比 |
|---|---|---|---|---|
| 基础 | 概念辨析 / 简答 | ~45% | 2-3 分 | ~30% |
| 中档 | 原理追问 / 小场景 | ~35% | 4-6 分 | ~35% |
| 大题 | 场景应用 / 故障排查 / 方案设计 | ~20% | 8-15 分 | ~35% |

前易后难，基础题在前、大题在后。**每题分值合计正好 100**（AI 算歪了服务端会校正）。

## 3. 答题（零 AI）+ 看答案计 0 分

```
 用户                 前端                      后端                 存储
  │ 写答案              │                         │                    │
  │ 点[保存并下一题]      │ POST /questions/{id}    │                    │
  │ ─────────────────> │   /attempts              │                    │
  │                    │ ───────────────────────> │ ★不调 AI            │
  │                    │                         │ ───────────────────>│ attempts.json
  │ 自动跳到下一题        │ 题号上打勾 ✓              │                    │
  │                    │                         │                    │
  │ 想看参考答案          │ ★先弹确认框               │                    │
  │                    │  「本题将计 0 分」          │                    │
  │ ─────────────────> │ POST /questions/{id}     │                    │
  │  确认后才看得到        │   /reveal               │ 打 revealedAt 标记   │
  │                    │ ───────────────────────> │ ───────────────────>│ questions.json
```

- 作答**追加保存**，历史不覆盖（同一题可改多次）
- **参考答案默认不给看**，只有点「看参考答案」并确认后才显示
- **看过参考答案的题，交卷时直接 0 分**，不交给 AI 批改（前后端口径一致）
- 保存后自动进下一题，不显示答案
- 答题页展示「本题要求」（demands）——批改只按它逐条核对，
  题干没问的内容不判缺失、不扣分，只进「扩展」段

## 3.1 容量上限

| 限制 | 默认 | 超了 |
|---|---|---|
| 每阶段练习数 | 50 | 拒绝新建，提示新建阶段 |
| 每练习卷数 | 20 | 拒绝出卷，提示新建练习 |

日常使用碰不到，只防数据无限膨胀。常量在 `Limits`。

## 3.2 练习与阶段没有「结束」

`complete` 接口已移除，练习与阶段一直保留。想收尾就新建一个阶段 / 练习。

## 4. 交卷（批改 + 总结 + 记忆 + 阶段总结）

**关键点：交卷后自动生成「阶段总结」，它是全复习的依据。**

```
 用户            前端                    后端                    AI              存储
  │ 点[交卷]       │                       │                      │                │
  │ ────────────> │ POST /papers/{id}     │ 校验: 有作答、是答题中  │                │
  │               │   /submit             │ status=grading        │                │
  │               │ ────────────────────> │ ────────────────────────────────────>│ papers.json
  │               │ <──────────────────── │ ★立即返回             │                │
  │               │                       │                      │                │
  │  看到批改进度   │ (轮询)                │ ┌──── 后台任务 ──────┐│                │
  │               │                       │ │ ①分批并发批改       ││                │
  │               │                       │ │  (每批 8 题)        ││                │
  │               │                       │ │ ─────────────────>│ score 0-10    │
  │               │                       │ │ <─────────────────│ feedback      │
  │               │                       │ │ 实得分=score/10×分值 ││                │
  │               │                       │ │ ────────────────────────────────────>│ attempts.json
  │               │                       │ │                   ││                │
  │               │                       │ │ ②③④ 三个调用并行    ││                │
  │               │                       │ │   ├ 本卷总结        ││                │
  │               │                       │ │   ├ L1 记忆更新     ││                │
  │               │                       │ │   └ L2 会话摘要     ││                │
  │               │                       │ │ ────────────────────────────────────>│ papers.summaryJson
  │               │                       │ │ ────────────────────────────────────>│ practices.memoryJson
  │               │                       │ │ ────────────────────────────────────>│ practices.digestJson
  │               │                       │ │                   ││                │
  │               │                       │ │ ⑤ ★阶段总结（必须    ││                │
  │               │                       │ │   排在②之后：它要读  ││                │
  │               │                       │ │   刚更新的记忆）      ││                │
  │               │                       │ │ ─────────────────>│ 固定格式喂数据 │
  │               │                       │ │ <─────────────────│                │
  │               │                       │ │ ────────────────────────────────────>│ stages.summaryJson
  │               │                       │ │                   ││                │
  │               │                       │ │ ⑥ 最后才            ││                │
  │               │                       │ │  status=graded      ││                │
  │               │                       │ └────────────────────┘│                │
  │  看到成绩      │                       │                      │                │
  │  ★此时阶段总结  │                       │                      │                │
  │    一定已就绪   │                       │                      │                │
  │  每题得分/点评  │                       │                      │                │
  │  本卷总结      │                       │                      │                │
```

**阶段总结的固定格式输入**（这是你说的那点，写死在 `StageSummaryService#dataText`）：

```
练习 1：《Java 并发编程》（主题模式）
  范围：……（范围模式才写）
  成绩：3 张卷、35 道题，百分制平均 62 分，最近一卷 68 分
  卷 1（得分 58/100）AI 评价：…… ← 每次考试的 AI 评价
  卷 2（得分 65/100）AI 评价：……
  卷 3（得分 68/100）AI 评价：……
  长期记忆：已掌握：……；薄弱点：……；已覆盖：……
  会话摘要：……
练习 2：……
```

**阶段总结的输出**：

```json
{
  "overall": "这个阶段练了什么、掌握到什么程度、最突出的问题",
  "strengths": ["已经掌握得比较好的方面"],
  "keyWeaknesses": ["最需要补的短板"],
  "nextSteps": ["下一步怎么练"],
  "reviewScope": "★ 为全复习框定的范围，一长串连贯的文字（200-400 字）"
}
```

`reviewScope` 会写清：覆盖了哪些大块 / 哪些练过（要覆盖但不出原题）/ 哪些是薄弱点要优先考 / 深度要求。

## 5. 网上资料（URL 真的会抓）

```
 用户                    前端                   后端                  网络            存储
  │ 范围描述里写            │                      │                    │               │
  │ 「参照 https://…」      │                      │                    │               │
  │                       │                      │                    │               │
  │ (可选) 点[探测链接]     │ POST /api/sources/   │                    │               │
  │ ────────────────────> │   probe               │                    │               │
  │                       │ ────────────────────> │ 从文本里抽 URL       │               │
  │  看到:                  │                      │ ──────────────────> │ HTTP GET      │
  │  「已抓到 3000 字」      │                      │ <──────────────────│ HTML          │
  │  或「读不到，请粘正文」   │                      │ HTML → 正文纯文本    │               │
  │                       │ <──────────────────── │ (去脚本/导航/页脚)   │               │
  │                       │                      │ ─────────────────────────────────>│ sources.json
  │                       │                      │                    │               │
  │            ———— 出题时 ————                     │                    │               │
  │                       │                      │ 从缓存取正文         │               │
  │                       │                      │ 拼进出题上下文        │               │
  │                       │                      │ 「网上资料（已抓取     │               │
  │                       │                      │  正文，出题以这些     │               │
  │                       │                      │  内容为准）」         │               │
```

**能读到**：服务端渲染的文档站、博客、wiki（实测 `javaguide.cn` 正常，抓到 3000+ 字正文）
**读不到**：纯前端渲染（SPA）的站点、需登录/有反爬的站点、PDF/图片/视频

读不到时**如实报错**（"网页里没有可读正文，请把内容复制粘贴进范围描述"），绝不装作读过。
抓一次就存住（`sources.json`），同一份资料不重复抓。

## 6. 全复习（基于阶段总结）

```
 用户                  前端                  后端                    AI
  │ 打开阶段详情          │                     │                      │
  │                    │ GET /api/stages/{id}  │                      │
  │                    │ ───────────────────> │ 实时统计(现算)          │
  │                    │ <─────────────────── │ summary(AI 阶段总结)   │
  │ 看到三块：           │                     │                      │
  │  ① 实时统计          │                     │                      │
  │  ② 阶段总结          │                     │                      │
  │  ③ [全复习] 按钮     │                     │                      │
  │                     │                     │                      │
  │  没有阶段总结 → 按钮禁用（后端也会拒绝）      │                      │
  │                     │                     │                      │
  │ 点[全复习]           │ POST /api/stages/   │ 没总结→400            │
  │ ─────────────────> │   {id}/review        │ 有总结→               │
  │                    │ ───────────────────> │  取 summary.reviewScope│
  │                    │                     │  建练习 review=true    │
  │                    │ <─────────────────── │  scopeText=reviewScope │
  │ 进入这个练习          │                     │                      │
  │ → 走 2/3/4 节流程    │                     │                      │
```

**全复习本质就是该阶段下的一个练习**，只是：
- 由系统创建（`review=true`），不是用户建的
- 范围不是用户写的，而是**阶段总结框定出来的一长串文字**

## 7. 记忆体系（不丢失 + 精简）

| 层 | 存哪 | 什么时候更新 | 硬上限 | 作用 |
|---|---|---|---|---|
| **L1 长期记忆** | `practice.memoryJson` | 每次交卷 | 每类 ≤8 条、每条 ≤30 字；coverage ≤40 条 | 已掌握 / 薄弱点 / 误区 / 下一步 / **已覆盖知识点** |
| **L2 会话摘要** | `practice.digestJson` | 每次交卷 | 全文 ≤400 字 | 总览 / 水平 / 已覆盖大块 / 未覆盖大块 |
| **L3 阶段总结** | `stage.summaryJson` | 每次交卷（自动） | reviewScope ≤600 字 | AI 反馈 + 全复习范围 |

**为什么不丢**：`coverage`（已覆盖知识点）走**并集累积**，服务端 merge、只增不减，
AI 只负责压缩措辞——压缩的是说法，不是知识点本身。

**上下文为什么不会超长**：LLM 调用本身无状态（每次独立 prompt），
所以"上下文过长"只可能来自 prompt 膨胀。出题 prompt 每段硬上限 + 总预算：

```
system(固定)
+ 范围描述      ≤ 2000 字
+ 网上资料正文   ≤ 6000 字
+ L2 会话摘要   ≤  600 字
+ L1 长期记忆   ≤ 1200 字
+ 最近历史      ≤ 15 条（超预算从最旧往回砍）
            ─────────────────────────────
                 总计 ≤ 12000 字
```

**会话恢复**：练习 `complete` 时写一份**收尾总结**（纯本地、永不失败），
重开会话直接读它，无缝衔接。

## 8. 状态机

**卷 Paper**

```
                ┌──────────────┐
   创建 ──────> │  generating  │ ──出题失败/进程被杀──┐
                └──────┬───────┘                     │
                       │ 全部题目生成完               │
                       ▼                             ▼
                ┌──────────────┐              [续跑] 从 planJson
                │  answering   │ <─────────────  断点接着出
                └──────┬───────┘
                       │ 点[交卷]
                       ▼
                ┌──────────────┐
                │   grading    │ ──批改失败──> [续跑] 已批的不重批
                └──────┬───────┘
                       │
                       ▼
                ┌──────────────┐
                │    graded    │   （终态）
                └──────────────┘
```

**断点续跑的三个保证**
1. `planJson` 落库 → 重跑时按原计划补缺的题，不会重复出
2. 每批成功立刻落库 → 中断不丢已完成的
3. `progressJson.running` → 任务真停了才显示「续跑」按钮（后端被杀也认）

## 9. 边界与失败处理

| 情况 | 行为 |
|---|---|
| 范围模式没填描述 | 建练习直接拒绝 |
| 没有阶段总结就点全复习 | 后端 400「请先生成阶段总结」，前端按钮禁用 |
| 阶段里还没有练习 | 生成阶段总结 / 全复习 都拒绝 |
| URL 抓不到（SPA/登录墙/PDF） | **如实报错**并提示粘正文，不装作读过 |
| 同一张卷还有没交的就出新卷 | 拒绝，提示先交卷 |
| 交卷时没有任何作答 | 拒绝，提示先答几题 |
| 已交卷的卷再交 / 再改作答 | 拒绝 |
| AI 少给了几道题 | 自动再补一轮（最多 3 轮） |
| AI 输出被截断 | 单批重试一次；批小到 5 题 |
| 后端中途被杀 | 进度还在库里，重开点「续跑」接着跑 |
| 旧数据有已删字段 | 读入时忽略，不报错 |
